# 수집 데이터 보관 위치 제안 (v0.1)

> 작성: ② 자료 수집팀 / 2026-11-24 — 대표 질문 "비공개 저장소는 어디에? 비용은 가급적 없이"에 대한 답
> 최종 설계는 ③ 프로그램팀 아키텍처와 맞춘다 (`teams/03-dev/INBOX.md` 전달)

## 1. 결론: "운영 머신 로컬 저장 + 무료 클라우드 백업" → 당분간 0원

| 역할 | 권고 | 비용 |
|---|---|---|
| **주 저장소** | 매매 시스템이 돌아가는 머신의 로컬 디스크에 Parquet 파일 + DuckDB로 조회 | 0원 |
| **백업 (암호화)** | Cloudflare R2 무료 구간(10GB) 또는 Backblaze B2 무료 구간(10GB) — rclone으로 매일 암호화 동기화 | 10GB까지 0원 ⚠ 재확인 |
| 10GB 초과 시 | Backblaze B2 (TB당 월 약 $6 → 50GB면 월 약 400원 수준) ⚠ 재확인 | 월 수백~수천 원 |
| 코드·문서·스키마 | 지금처럼 GitHub 저장소 | 0원 |

## 2. 용량 추정 (Parquet 압축 기준, 대략)
| 데이터 | 규모 |
|---|---|
| 국내 일봉 15년 + 재무·공시 | 수백 MB |
| 미국 일봉 10년 | 수백 MB |
| 국내 분봉 (1년 백필 + 매년 적재) | 연 약 1GB |
| 미국 분봉 5년 백필 + 매년 적재 | 5년 약 5GB, 이후 연 약 1GB |
| **합계 (P1~P3)** | **10GB 안팎** → 무료 구간에서 시작 가능 |

## 3. 왜 이 안인가 / 다른 선택지

| 선택지 | 판단 | 이유 |
|---|---|---|
| GitHub 비공개 저장소 | **부적합** | 파일 100MB 제한, 저장소 수 GB 권장 한도, LFS 무료 1GB. 데이터가 매일 바뀌어 이력이 폭증. 코드 저장소와 데이터를 섞으면 실수로 공개될 위험 |
| Google Drive / OneDrive (개인 무료 용량) | 백업 차선책 | 무료 15GB(구글)지만 자동화·파일 다수 동기화에 불안정. 개인 계정 연동 위험 |
| Oracle Cloud Always Free VM (블록 스토리지 포함) | 프로그램팀 검토 대상 | 서버와 저장소를 0원에 함께 해결할 수 있으나 무료 자원 회수·가용성 리스크. 운영 서버 결정은 프로그램팀 소관 |
| AWS S3 / GCP Storage | 비권장 (지금) | 소액이지만 과금 발생, 데이터 반출(egress) 비용 |

## 4. 운영 원칙
1. 원본(raw)은 append-only, 날짜별 파티션(`market=KR/date=YYYY-MM-DD/`)
2. 백업은 **암호화**(rclone crypt) 후 업로드 — 시세 재배포 금지 약관 및 계좌 관련 정보 보호
3. API 키·백업 키는 저장소에 커밋 금지 (환경변수/시크릿)
4. 월 1회 백업 복구 리허설 (실제로 되살려 봄)
