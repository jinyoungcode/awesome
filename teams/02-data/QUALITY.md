# 데이터 품질 점검 기준 (v0.1 초안)

> 작성: ② 자료 수집팀 / 2026-11-23
> 목적: P1 Gate "**데이터 품질 리포트 통과**"의 합격 기준을 정의한다.
> 등급: **BLOCK** = 해당 배치 적재 중단·알림 / **WARN** = 적재하되 리포트에 기록·수동 확인 / **INFO** = 통계만 기록

## 1. 점검 항목

### A. 결측 (Completeness)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| A1 | 거래일 누락 | 개장일(`trading_calendar.is_open`)인데 유니버스 종목 일봉 행이 없음 (거래정지 제외) | BLOCK |
| A2 | 필드 결측 | 비정지 종목의 OHLCV 중 null 존재 | BLOCK |
| A3 | 일별 종목수 급변 | 시장별 수집 종목수가 전일 대비 ±2% 초과 변동 | WARN |
| A4 | 재무 결측 | 정기보고서 제출 기한(분기 45일, 사업보고서 90일) 경과 후 유니버스 종목 재무 미수집 | WARN |

### B. 정합성 · 이상치 (Validity)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| B1 | 가격 논리 | `low ≤ min(open, close) ≤ max(open, close) ≤ high`, 모든 가격 > 0 | BLOCK |
| B2 | 가격제한폭 | 원주가 일간 변동률이 ±30%(+호가단위 오차) 초과인데 해당일 `corporate_action`·신규상장·정리매매 없음 | BLOCK |
| B3 | 거래대금 정합 | `value` ≈ `volume` × 평균가, 비율이 [low, high] 범위를 벗어남 | WARN |
| B4 | 시총 정합 | `market_cap` ≈ `close` × `shares_outstanding` (오차 0.5% 초과) | WARN |
| B5 | 상장주식수 변동 | 주식수 변동이 있는데 대응되는 기업이벤트·공시 없음 | WARN |
| B6 | 무거래 연속 | 비정지 종목이 거래량 0으로 5거래일 이상 연속 | WARN |
| B7 | 재무 항등식 | 자산 = 부채 + 자본 (오차 0.1% 초과) | WARN |

### C. 교차검증 (Accuracy)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| C1 | 소스간 종가 비교 | KRX Open API 종가 vs 2순위 소스(공공데이터포털/KIS) 종가 불일치 — 표본 일 50종목 | 1건 이상 WARN, 1% 초과 BLOCK |
| C2 | 지수 재현 | 구성종목·시총으로 재계산한 KOSPI200 일간 수익률 vs 공표지수 수익률 차이 > 0.1%p | WARN |

### D. 생존편향 (Survivorship)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| D1 | 상폐 종목 포함 | 백테스트 기간 중 상폐된 종목이 `instrument_master`와 `daily_price_raw`에 존재 (KRX 상폐 목록과 대조, 누락 0건) | BLOCK |
| D2 | 지수 이력 | 임의 과거 정기변경일 표본 3개 시점의 구성종목 수가 200/150과 일치하고, 거래소 공표 편입·편출 목록과 일치 | BLOCK |
| D3 | 코드 재사용 | 동일 `ticker`가 서로 다른 `isin`에 매핑된 이력 탐지 → `isin` 기준 분리 확인 | WARN |

### E. 수정주가 (Adjustment)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| E1 | 이벤트일 연속성 | 분할·병합·무상증자 `ex_date` 전후 수정주가 수익률이 ±30% 이내이고, 원주가 갭은 계수로 설명됨 | BLOCK |
| E2 | 계수 근거 | 모든 계수 변화 행에 `corporate_action.rcept_no` 근거 존재 | BLOCK |
| E3 | 외부 대조 | 표본 20개 이벤트에 대해 자체 수정주가 vs 증권사 HTS 수정주가 비교 (차이 0.5% 이내) | WARN |
| E4 | 재현성 | 같은 `version` 계수로 재계산 시 결과가 비트 단위 동일 | BLOCK |

### F. 시점 정합 (Point-in-time / Look-ahead)
| ID | 점검 | 기준 | 등급 |
|---|---|---|---|
| F1 | 재무 사용 가능일 | 모든 재무 행에 `available_date` 존재, `available_date > 공시 접수일` | BLOCK |
| F2 | 정정공시 | 정정 전 원본값 보존 (덮어쓰기 금지) | BLOCK |
| F3 | 적시성 | 일봉 18:30까지, 재무·공시 21:00까지 적재 완료 | WARN (3일 연속 시 BLOCK) |

## 2. 품질 리포트 형식 (일일 / P1 Gate용 누적)

- 일일: 점검 ID별 통과/실패 건수, 실패 상세(종목·일자·값), 처리 상태 → `reports/quality/YYYY-MM-DD.md` (경로는 프로그램팀 설계에 따름, **데이터 값은 저장소 커밋 금지·요약만**)
- **P1 Gate 합격 기준 (제안):**
  1. 백테스트 대상 전 기간에 대해 BLOCK 항목 미해결 0건
  2. WARN 항목은 전량 원인 분류(원천 오류/정상 이벤트/미확인) 완료, 미확인 비율 0.1% 이하
  3. D1·D2·E1~E4 표본 검증 결과를 첨부하고 매매팀·총괄 확인 서명

## 3. 데이터 이슈 처리 절차
1. 탐지 → 2. 원천 재수집 → 3. 2순위 소스 대조 → 4. 수동 보정 시 `source=MANUAL` + 근거 기록 → 5. 리포트 반영
수동 보정은 원본을 덮어쓰지 않고 보정 레이어에만 기록한다.
