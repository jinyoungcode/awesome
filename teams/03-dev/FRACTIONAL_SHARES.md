## 1. 결론 요약

| 항목 | 확인 결과 | 확신도 |
|---|---|---|
| KIS Open API 미국 소수점 **주문** API | 공식 GitHub 샘플·공개 자료 어디에서도 **확인되지 않음**. KIS의 미국 소수점 거래는 별도 앱 **미니스탁**에서 제공되고, **실시간 거래가 아님**(회차별 일괄 처리) | 중 — 포털 문서 직접 확인 필요 |
| KIS Open API 국내 소수점 **주문** API | **확인되지 않음** | 중 |
| 국내 소수점 거래 제도 구조 | 신탁 수익증권 방식: 증권사가 주문을 **회차별로 모아** 부족분을 자기 물량으로 채운 뒤 1주 단위로 거래소에 주문. **가격 지정 불가**, 실시간 아님, 주주권 일부 제한. 2025년 자본시장법 시행령 개정으로 제도화 추진 | 높음 (언론·약관) |
| 모의투자 지원 | 소수점 주문 API 자체가 확인되지 않아 **모의투자 지원 근거 없음** | 중 |
| 데이트레이딩(D-007/D-018)과의 정합성 | 소수점 체결은 **가격 지정 불가 + 회차 일괄** → 분봉 데이트레이딩의 진입·청산가 통제가 불가능. **데이트레이딩 전략에는 쓸 수 없음** | 높음 |

**권고:** D-019는 "API로 가능한 경우에만"이라는 조건부 결정이므로, 현재 증거로는 **소수점 거래는 P3 모의투자 범위에서 제외**하고 정수 주식으로 진행합니다. 다만 수량 타입은 나중에 소수점을 켤 수 있게 **지금 미리 바꿔 두는 안(§3)** 을 제안합니다. 10만 원 단계의 고가주 문제는 §4의 대안으로 먼저 풉니다.

## 2. 왜 중요한가 — 10만 원 단계의 고가주 제약 (수치)

PR #2 규칙: 주문 목표 = 100,000원 ÷ 5 = **20,000원**, 허용 범위 90~110% = **18,000~22,000원**.

| 종목 예 | 1주 가격(대략) | 1주 주문 가능? |
|---|---|---|
| 국내 1주 22,000원 이하 종목 | ≤ 22,000원 | 가능 (예: 7,000원 × 3주 = 21,000원) |
| 국내 1주 22,000원 초과 종목(대형주 다수) | > 22,000원 | **불가** (1주만 사도 110% 초과) |
| 미국 대형주 대부분 | 수십만 원 | **불가** |

→ 10만 원 단계에서는 미국 대형주와 국내 대형주 대부분을 살 수 없습니다. 소수점 거래가 풀어 주려던 문제가 바로 이것입니다.

## 3. 수량 타입 변경 설계안 (구현 보류, 승인 시 별도 PR)

### 3.1 원칙
1. **수량은 `Decimal`, 금액은 원 정수 그대로.** float는 0.1+0.2 오차 때문에 수량에 쓰지 않습니다.
2. **종목별 최소 주문 단위(`lot_step`)** 를 둡니다. 기본은 `1`(정수 주식). 소수점이 허용된 종목만 예: `0.000001`.
3. **소수점은 기본 꺼짐.** `fractional_enabled`는 종목(또는 시장)과 브로커가 **둘 다** 지원할 때만 켜집니다. 지금은 KIS 어댑터가 `supports_fractional = False`이므로 모든 소수 수량은 관문에서 거부됩니다(fail-closed).
4. **체결 방식이 다르면 주문 유형도 분리합니다.** 소수점 체결은 "가격 지정 불가·회차 일괄"이므로 `OrderType.FRACTIONAL_BATCH`를 따로 두고, 데이트레이딩 전략은 이 유형을 낼 수 없게 막습니다.

### 3.2 바뀌는 곳

| 파일 | 현재 | 변경안 |
|---|---|---|
| `domain.py` `OrderRequest.quantity` | `int`, ≥1 | `Decimal`, >0. `int` 입력은 자동 변환(기존 코드 호환) |
| `domain.py` `Position.quantity`, `Fill.quantity` | `int` | `Decimal` |
| `domain.py` 신규 `Instrument` | 없음 | `symbol, market, lot_step: Decimal = 1, fractional_enabled: bool = False` |
| `domain.py` `AccountSnapshot.equity` | `quantity * price` (정수) | `Decimal` 곱 → **원 미만 절사 후 int** (평가금액 보수적 계산) |
| `sizing.py` `shares_for_target` | 정수 주식 수 후보(내림/올림) | `lot_step` 배수로 내림한 수량. `lot_step=1`이면 지금과 결과 동일 |
| `risk/gate.py` | — | 신규 검사 **`LOT_STEP`**: 수량이 `lot_step` 배수가 아니면 거부. **`FRACTIONAL_NOT_SUPPORTED`**: 소수 수량인데 브로커/종목이 미지원이면 거부. 주문금액 = `floor(price × qty)` |
| `backtest/engine.py` | 정수 수량 | `Decimal` 수량. 소수점 체결 가정을 쓰면 결과 `warnings`에 **"소수점 체결 가정(실제 API 미확인)"** 표기 |
| `broker/base.py` | — | `supports_fractional: bool` 속성 추가 |
| `broker/kis.py` | `ORD_QTY=str(int)` | 정수가 아니면 **전송 전 예외**(이중 안전장치). 소수점 API 확인 시 별도 메서드로 추가 |
| `broker/paper.py` | 정수 | `Decimal` 지원(로컬 시뮬용) |
| 감사 로그·장부 | 정수 | 수량을 **문자열 Decimal**로 기록(`"0.123456"`) — 회계팀 장부 포맷에 반영 요청 |

### 3.3 하위 호환·테스트 계획
- `lot_step=1`, `fractional_enabled=False`가 기본이라 **기존 테스트 전부가 결과 변화 없이 통과해야 함**(회귀 기준).
- 신규 테스트: 소수 수량 거부(미지원 브로커), `lot_step` 배수 검사, `Decimal` 평가금액 절사, KIS 어댑터의 소수 수량 전송 차단, 백테스트 소수점 가정 경고.
- 예상 작업량: 약 1~1.5일(구현+테스트), PR #2 머지 이후 착수.

## 4. 소수점 없이 10만 원 단계를 운용하는 대안 (리스크실·매매팀 협의 필요)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 가격대 유니버스 | 10만 원 단계에선 1주 가격 ≤ 22,000원 종목만 대상 | 지금 코드로 바로 가능 | 미국 대형주 제외, 유니버스 편향 |
| B. 슬롯 축소 | 10만 원 단계에선 동시 보유 5 → 2~3종목(목표 33,000~50,000원) | 살 수 있는 종목이 넓어짐 | 분산 감소 — D-003 "최대 5종목" 범위 안이지만 리스크실 확인 필요 |
| C. 1주 예외 | 1주가 목표 범위를 넘으면 1주까지는 허용(단 1종목 비중 22% 한도는 유지) | D-014 "1주 고정" 예외안과 같은 방향 | 비중 한도와 충돌하는 종목은 여전히 불가 |
| D. 소수점 확인 후 도입 | KIS 포털·고객센터 확인 → API가 있으면 §3 구현 후 스윙 전략에 한해 사용 | D-019 취지 충족 | 데이트레이딩에는 불가(§1) |

**프로그램팀 권고:** 우선 **A+C**로 P3 모의투자를 시작하고, 병행해서 D를 확인합니다. 소수점 API가 확인되면 스윙(1~5거래일) 전략에만 적용합니다.
