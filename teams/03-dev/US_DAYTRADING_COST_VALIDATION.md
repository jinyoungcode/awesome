# 미국 데이트레이딩 비용 반영 검증 방법 (D-035) — 초안 v0.1

> 작성: 프로그램 생성팀 / 2026-11-24 · 요청: 총괄(Codex PR #2 리뷰 "개발팀 검증 방법")
> 적용 대상: D-018 미국 데이트레이딩. **D-033에 따라 T0(15만 원)는 국내 S02만 운용**하므로, 이 문서는 미국 데이트레이딩 가동 승인 요청 전에 쓰는 절차입니다.
> 판정 기준(통과선)은 매매팀·리스크관리실 협의로 확정합니다. 이 문서는 **측정 방법과 재현 절차**를 정합니다.

## 1. 원칙

1. **비용은 가정이 아니라 실측이 기준입니다.** 회계팀의 왕복 0.60%는 실측 전 검증용 가정치입니다(D-035).
2. **별도 검증 구간(holdout)** 은 전략 설계와 파라미터 조정에 한 번도 쓰지 않은 기간이며, 판정에 딱 한 번만 씁니다. 다시 돌려 결과를 고르면 무효입니다.
3. **비용을 올려도 순성과가 양수**여야 가동 승인을 요청할 수 있습니다.
4. 같은 커밋·같은 데이터·같은 설정이면 같은 결과가 나와야 합니다. Codex가 독립적으로 다시 실행해 확인합니다.

## 2. 측정할 비용 항목

| 항목 | 기호 | 실측 출처 | 실측 전 가정(회계팀 COST_MODEL v0.2) |
|---|---|---|---|
| 위탁수수료 | c_comm | KIS 해외 체결내역(자동매매 전용 계좌 API 주문, D-030) | 편도 0.25% |
| SEC fee (매도) | c_sec | 체결내역의 제비용 | 0.00206% (2026-04-04 결제분부터) |
| FINRA TAF (매도) | c_taf | 동일 | $0.000195/주, 최대 $9.79 |
| 호가 스프레드 | c_spread | 주문 직전 1분봉 또는 호가 스냅샷의 (매도호가 − 매수호가)/2 | 종목별 측정 |
| 슬리피지 | c_slip | (체결가 − 신호 기준가)/신호 기준가, 매수 +·매도 − | 시장성 지정가 ±0.5% 범위 안 |
| 환전 비용 | c_fx | `fx_conversions.csv`의 \|적용환율 − 매매기준율\| | 회계팀 C-4 |
| 미체결 기회비용 | — | 시장성 지정가 미체결 건수 / 전체 신호 | 측정만 하고 성과에서는 '거래 없음'으로 처리 |

**왕복 총비용(bp)** = 2·c_comm + c_sec + c_taf/가격 + 2·c_spread + |c_slip|(매수) + |c_slip|(매도) + 2·c_fx(1회전당 배분)

## 3. 실측 절차 (모의 → 전용 계좌 소액)

1. **모의투자에서 경로 점검:** 주문·체결·장부 경로만 확인합니다. KIS 모의 체결은 실제 호가·수수료와 다를 수 있으므로 **비용 실측에는 쓰지 않습니다**.
2. **자동매매 전용 계좌(D-030)에서 미국 소액 실주문:** 가동 승인 전 측정 목적의 실주문은 별도로 대표 승인을 받아야 합니다. 1주 단위로 유동성 상위 10종목, 시간대 3구간(개장 30분·장중·마감 30분), 매수·매도 각 30건 이상을 목표로 합니다.
3. 체결 1건마다 trades.csv에 commission, sec_fee, finra_taf, fx_rate를 기록하고, 신호 기준가·주문가·체결가·호가 스냅샷을 감사 로그에 남깁니다.
4. 집계 결과: 항목별 평균·중앙값·상위 5%(p95) bp, 시간대별·종목별 분해 → `var/cost_measurement/us_YYYYMMDD.json`

## 4. 백테스트 검증 설계

### 4.1 기간 분할 (분봉, D-017 예산 내 데이터)
| 구간 | 용도 | 규칙 |
|---|---|---|
| 개발 구간 | 전략 설계, 파라미터 탐색 | 워크포워드: 학습 N개월 → 다음 1개월 검증, 굴리면서 반복 |
| **별도 검증 구간** | 최종 판정 1회 | 개발 구간 이후 **최근 연속 3개월 이상**. 데이터 해시와 기간을 판정 전에 문서로 고정(아래 §6) |

### 4.2 비용 시나리오 (모두 같은 신호, 비용만 바꿔 재계산)
| 시나리오 | 내용 |
|---|---|
| S0 실측 | §3 평균값 |
| S1 실측 p95 | 항목별 상위 5% 값 |
| S2 가정 | 회계팀 왕복 0.60% |
| S3 스트레스 | max(S1, S2) × 1.5 |
| S4 스트레스+ | 스프레드·슬리피지만 ×2 (빠른 장에서 더 커지는 성분) |
| BE 손익분기 | 순성과 = 0 이 되는 왕복 비용(bp)을 이분 탐색으로 계산 → **비용 여유 = BE − S0** |

### 4.3 보고 지표 (별도 검증 구간, 시나리오별)
순수익률, 1거래당 평균 순손익(bp)과 부트스트랩 95% 하한, 거래 수, 승률, 손익비, MDD, 일별 수익률 샤프, 비용이 총이익에서 차지하는 비율, 비용 여유(BE − S0).

### 4.4 판정 제안 (매매팀·리스크실 확정 필요)
- **필수:** S3 시나리오 순수익률 > 0 **그리고** 1거래당 평균 순손익의 부트스트랩 95% 하한 > 0
- **필수:** 비용 여유 BE ≥ 2 × S0
- **필수:** 별도 검증 구간 거래 수 ≥ 100회
- 참고: S4, 시간대별 분해에서 특정 시간대만 손실이면 해당 시간대 제외안을 매매팀이 검토 (제외한다면 개발 구간에서 다시 설계하고 새 별도 검증 구간이 필요)

## 5. 무인 운용 조건(U1~U7)과의 연결
비용 검증과 별도로 D-018 U1~U7(`teams/04-trading/DAYTRADING_REVIEW.md` §8)은 운영 점검표로 확인합니다. 두 가지를 모두 충족해야 대표에게 가동 승인을 요청합니다(D-035).

## 6. 재현성 (Codex 독립 재실행용)
판정 전에 다음을 커밋으로 고정합니다: 코드 커밋 ID, 설정 파일(전략·비용 시나리오), 데이터 파일 목록과 SHA-256 해시, 별도 검증 구간 시작·종료일, 난수 시드(부트스트랩). Codex는 같은 커밋에서 아래 명령 한 줄로 같은 숫자를 재현해야 합니다.
