# 저장소 구조 · 코딩 규칙 · 테스트 정책 (1차 과업 #4)

## 1. 저장소 구조

```
docs/                 조직·결정 기록 (총괄 관리)
teams/<팀>/           팀별 문서, INBOX.md 로 팀 간 요청
src/stockking/
  config.py           운용 모드(BACKTEST/PAPER, LIVE 차단), 비밀값 로딩
  domain.py           주문·체결·포지션 타입 (원·주 단위 정수)
  risk/               리스크 관문, 킬스위치
  execution/          주문 라우터 (유일한 주문 통로)
  broker/             증권사 어댑터 (paper=로컬 시뮬, kis=KIS 모의투자)
  backtest/           백테스트 엔진, 비용모델, 성과지표, CLI
  data/               데이터 형식·로더
  strategy/           전략 인터페이스 (전략별 파일)
  audit/              감사 로그
tests/                pytest
var/  (gitignore)     킬스위치 파일, 토큰 캐시, 런타임 로그
.env  (gitignore)     비밀값 — 절대 커밋 금지
```

## 2. 코딩 규칙

1. **Python 3.11+**, 코어는 표준 라이브러리만. 외부 의존성 추가는 아키텍트 승인 + `pyproject.toml` 기록.
2. **돈은 정수(원), 수량은 정수(주).** float 는 비율·지표에만. 수수료·세금은 원 미만 절사(회계팀 확인 후 조정).
3. **전략은 주문하지 않는다.** `TargetOrder` 만 반환. 브로커 직접 호출 금지(리뷰에서 반려).
4. **Fail-closed.** 판단 불가 상황(데이터 누락·예외)은 '거래 안 함'이 기본.
5. **주문 자동 재전송 금지.** 상태 불명확 시 조회 후 사람이 판단.
6. **비밀값**: 코드·문서·테스트·로그·커밋 메시지 어디에도 실제 값 금지. 예시는 빈 값 또는 `xxxx`.
7. 증권사별 코드(TR ID, 필드명)는 `broker/<증권사>.py` 안에만. 공식 문서 미확인 값은 주석에 "재확인 필요" 표기.
8. 브랜치: 팀 브랜치(`claude/stock-king-03-dev`)에서 작업 → PR 로 머지. 리스크 관문·모드·브로커 변경은 리스크실 리뷰 필수.
9. 커밋 메시지: `[영역] 요약` (예: `[risk] 주간 손실 한도 추가`).

## 3. 테스트 정책

| 구분 | 기준 |
|---|---|
| 실행 | `python -m pytest` — 머지 전 전부 통과 필수 |
| 리스크 관문 | **한도 항목마다 승인/거부 테스트 1쌍 이상**. 관문 코드 변경 시 테스트 동반 필수 |
| 안전 장치 | LIVE 차단, 실전 도메인 거부, 비모의 브로커 거부, 비밀값 미커밋 — 항상 유지 (삭제·skip 금지) |
| 백테스트 | 체결 시점(D+1 시가), 비용 반영, 무비용·횡보 시 자산 보존, 거래정지 미체결 |
| 네트워크 | 단위 테스트는 실서버 호출 금지(가짜 transport). 모의투자 서버 통합 테스트는 별도 마커로 수동 실행 |
| 회귀 | 버그 수정 시 재현 테스트 먼저 추가 |
