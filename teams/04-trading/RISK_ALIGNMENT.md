## 2. 손실 한도·킬스위치 단계 (매매팀 제안)

| 단계 | 발동 조건 (총자산 기준, 종가 판정) | 조치 | 해제 |
|---|---|---|---|
| K1 일간 경보 | 당일 손익 ≤ **−3%** | 다음 거래일 **신규 진입 중단** (청산은 정상 진행), 대표 알림 | 1거래일 후 자동 해제 |
| K2 월간 축소 | 당월 누적 손익 ≤ **−6%** | 그달 남은 기간 동안 신규 진입 사이징 **50%** (L1을 0.25%로) | 다음 달 첫 거래일 |
| K3 전략 정지 | 슬리브 고점 대비 낙폭: S01 −25%, S02 −20%, S03 −20% (EVALUATION G2 백테스트 MDD 한도와 동일) | 해당 전략 신규 진입 중단(SUSPENDED), 보유분은 청산 규칙대로 정리, 3자 재검토 | 재검토 후 총괄 승인 |
| K4 계좌 킬스위치 | 계좌 고점 대비 낙폭 ≤ **−15%** | 개별주 전략 전체 신규 진입 중단, 대표 보고 | 대표 승인 |
| K5 전량 청산 | 계좌 고점 대비 낙폭 ≤ **−20%** (= 허용 MDD) | **전 포지션 T+1 시가 청산 (X_KILL)**, 시스템 정지 | 대표 승인 + 원인 보고서 |
| K6 시스템 이상 | 데이터 QC 실패, 장부 대사 불일치, 주문 오류 3회 이상 | 신규 주문 중단 (청산 주문은 수동 확인 후) | 프로그램팀 원인 해소 + 총괄 확인 |

- 낙폭 한도값(K4, K5)은 대표의 허용 MDD 결정(Q-T02)에 연동됩니다. 허용 MDD를 X%로 정하면 K4 = 0.75X, K5 = X로 둡니다.
- 모든 한도 검사는 프로그램팀이 **주문 직전 필수 관문(리스크 관문)**으로 구현합니다(조직안 ③ 1차 과업 3번). 관문에서 탈락한 주문은 사유 코드와 함께 기록합니다.

## 3. 리스크관리실에 확인 요청하는 사항

1. 위 L1~L8, K1~K6 값을 승인할지, 아니면 수정할지 (특히 K5: 계좌 낙폭 −20%에서 전량 청산하는 것이 대표 성향과 맞는지)
2. 킬스위치 발동 후 **재개 권한자** (제안: K1·K2는 자동, K3는 총괄, K4·K5는 대표)
3. 긴급 중단 시 집행 방식: 다음 날 시가 일괄 청산과 즉시 정규장 시장가 청산 중 무엇을 기본으로 할지 (제안: 다음 날 시가. 장중 패닉 매도를 피하기 위해서)
4. 컴플라이언스: 본인 계좌 자동매매 시 증권사 API 약관상 주문 횟수 제한·자동주문 고지 의무가 있는지 (S01·S02의 하루 주문 수는 최대 약 20건으로 예상)
